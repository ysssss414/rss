# Stage 1 foundation — HistoricalUniverse and ExecutionPolicy

This implementation is based on public `main` `29baa0603a5279c91b80e47aad9c7ecc6886656b` (Gate C PR #9 merge). Gate C remains `GATE_C_CONTRACT_PASS`; C1/C2 are closed at the contract level. Gate B's `DailyTradingConstraint` is the source of validated daily limit semantics. The code accepts normalized, frozen inputs; it does not fetch a market-wide historical master or qualify any live provider coverage.

`HISTORY_REQUIREMENT = DEPENDENCY_DRIVEN`. Legacy `warmup_trading_days=150` requests optional indicator warm-up; it is not a Stage 1 listing-age filter. `HistoricalUniverse` requires an explicit `minimum_history_required` in every evaluation. The foundation has no admitted primitives, so zero is permitted; future primitive registration must supply the maximum required lookback in its frozen run context. The 20 unchanged Gate C expected outcomes are exercised with the fixtures' explicit seven-observation scenario. No 150 constant enters the engine.

`HistoricalUniverse.evaluate` returns a frozen `UniverseRecord` for a security-day. It uses dated security type, verified lifecycle events, explicit trading status, the canonical Gate B validated 10% constraint, and the valid T bar at the Gate C decision cutoff. It counts distinct exchange sessions with `TRADING` status, a valid source-hashed PIT stock EOD bar, and matching frozen snapshot since the latest listing or relisting. Calendar days, missing/suspended bar days and 10%-eligible historical days are separate concepts. T can count only after its final bar is available. The result carries a primary Gate C reason and additional structured exclusions when multiple inputs fail. Unknown, conflicting or late evidence never becomes eligible. Ticker prefixes, current names, ST flags and raw percentage changes are not used as universe authority.

`ExecutionPolicy` registers `NEXT_SESSION_V1` only. Its input is a causal T EOD signal, side, frozen calendar and next-session market context. It models a 09:15 order and 09:25 opening-auction decision on the next listed exchange session; it never adds one calendar day. A validated pre-open Gate B constraint, trading state and positive on-tick raw open strictly below its upper limit produce `MODELLED_FILL` at the raw open with explicit idealized zero slippage. Open exactly at the limit produces `NO_FILL`. Missing/invalid constraint or open, open above the limit, suspension, non-trading, non-session signal and no following session produce `EXECUTION_UNRESOLVED` without a fabricated price or automatic rollover. `CLOSING_AUCTION_V1` and `PRE_CLOSE_SNAPSHOT_V1` raise `NOT_QUALIFIED`; no same-day fill model is exposed. A modeled fill is not evidence of actual broker execution, quantity or queue position. The baseline implements BUY only; other sides require a separate qualified policy.

The later [trade-lifecycle extension](stage1_trade_lifecycle_exit_contract.md) preserves this BUY policy unchanged and separately registers `NEXT_SESSION_SELL_V1`. Its symmetric lower-limit boundary is conservative: a valid on-tick raw open strictly above the lower limit is a modeled fill, an open exactly at limit down is `NO_FILL`, and missing or invalid evidence is `EXECUTION_UNRESOLVED`.

`RunContext` freezes the data snapshot, Gate B and Gate C versions, execution policy ID/version and calendar version. The caller must provide a qualified calendar and normalized as-of security/lifecycle/constraint/bar inputs. Tests use only synthetic calendars and synthetic cases; the repository still has no qualified complete historical security master, so no market-wide or real-data smoke claim is made. No RSI/MA signal, limit-up observation pool, entry/exit logic, PnL, optimization, production mutation or broker integration is included.
