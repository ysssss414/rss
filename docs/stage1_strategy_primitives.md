# Stage 1 strategy primitives — contract and implementation

This branch starts from public `main` `33e2161b0b1d59a75321f54937b6647c5de26da0`, the merge commit of foundation PR #10. It implements primitive values only. No observation pool, entry, exit, backtest, PnL or production feed is added.

## Definition sources and price lineage

The historical RSI authority is [`three_board_rsi_entry/indicators.py`](../three_board_rsi_entry/indicators.py) and [`docs/three_board_rsi_entry_v0.1.md`](three_board_rsi_entry_v0.1.md), version `v0.1`: Tonghuashun `SMA(GAIN,14,1)/SMA(ABS(delta),14,1)*100`, with both recurrences seeded by the **first valid delta**. It is not the alternative Wilder 14-delta SMA seed. The first numerical RSI can occur at the **second valid price**, although reproducing its later state requires the entire valid price prefix since the latest listing/relisting (or a separately frozen prior state). If all smoothed absolute changes are zero, the historical result is undefined; the new readiness is `DEPENDENCY_INVALID`, not a fabricated 50. Strictly rising and falling prefixes yield 100 and 0. Numeric calculations use decimal arithmetic with 28 significant digits and half-even rounding; this version is `RSI14_PROJECT_V1`, preserving the formula while making precision explicit. Legacy `warmup_trading_days=150` remains optional research warm-up, never universe eligibility.

Legacy MA5 is the simple mean of the latest five valid stock trading closes, from the same source. The new `MA5_SMA_V1` begins at five valid indicator-price observations. Explicit suspension rows do not create synthetic prices; invalid or missing trading-day rows cannot be silently skipped. All primitive histories reset at the latest dated listing/relisting boundary.

The indicator price basis is `PIT_ADJUSTED_CLOSE_V1`, reusing the Stage 0 [`adjusted_bars` formula](../research/data/adjustment.py) `raw_close(date) * factor(date) / factor(T)`, with T as the frozen decision anchor. Each price record carries security/date, basis, availability, snapshot and validity. The builder requires explicit complete calendar/status coverage, a frozen snapshot, declared daily or effective-event factor schema, positive factors, source hash, and a separately verified PIT factor source. It rejects factors unavailable at T and ignores all future effective rows before validation. This qualifies the **input contract and synthetic construction**, not a real AmazingData factor history: the current vendor's latest-query forward-adjusted series is not admitted as historical PIT evidence. Until a factor source is independently qualified, real-data primitive runs fail closed.

The raw official trading close is a separate lineage. `IS_CLOSE_LIMIT_UP_V1` compares that raw close with Gate B's validated raw upper limit using `Decimal` and the price tick. It requires an explicitly typed A-share common stock and returns a ready true/false value or `INVALID_INPUT`; adjusted indicator prices and percentage-change heuristics are not accepted. This event primitive can identify 10%, 20% and 5% close-limit events. `LIMIT_UP_COUNT_5_V1` then examines the last five qualified EOD stock observations through T, skipping only explicit suspensions. Every observation in its window must have a valid Gate B constraint and a symmetric qualified 10% regime. A historical 5% or 20% event makes the **window** `DEPENDENCY_INVALID`, even when T itself is in the 10% universe. Fewer than five observations give `NOT_ENOUGH_HISTORY`; invalid constraints, missing sessions or bars never become zero events. No count threshold or trading action is applied.

All primitive outputs use `READY`, `NOT_ENOUGH_HISTORY`, `INVALID_INPUT` or `DEPENDENCY_INVALID`; only `READY` carries a value. Availability is the latest admitted input availability and never precedes finalized T EOD. The [versioned registry](../research/dependencies.py) reports separate minimum indicator-price and limit-constraint history: with MA5, RSI14 and LimitUpCount5 enabled, both are five observations and the base minimum is five. This is only the earliest readiness count: `RSI14_PROJECT_V1` requires the full valid prefix from the latest listing/relisting reset, not an arbitrary recent five prices. The graph and [`PrimitiveRunContext`](../research/dependencies.py) explicitly freeze that replay origin, data snapshot, universe contract, indicator basis, primitive versions and graph version. The source calendar is separately frozen in the price series and limit-window input.

`RSI_WARMUP_POLICY_V1` later hardens the distinction between the two-observation numerical readiness, canonical full-prefix replay, and a non-canonical truncated research slice. A truncated slice requires at least 120 observations and targets 150 by default. Those convergence counts are not `HistoricalUniverse` eligibility: if only 80 observations exist since listing, all 80 form the canonical available prefix. See the [warm-up and lifecycle contract](stage1_trade_lifecycle_exit_contract.md).

The [golden cases](../artifacts/stage1_strategy_primitives/golden_validation_cases.json) show hand-computable RSI recursion, MA5, limit windows, a split-adjustment example, regime transitions, PIT rejection and lifecycle reset. These are synthetic contract tests. A complete qualified historical PIT master/calendar and a qualified live factor history are not available; no market-wide primitive validation or strategy result is claimed.
