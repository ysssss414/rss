### SSE acquisition

The [SSE market-data file specification, June 2026](https://www.sse.com.cn/services/tradingtech/development/c/10822594/files/2096257019bf484f9b9935fa73f94721.pdf) defines pre-open `cpxx0201MMDD.txt`, distributed by MDGW/ztDisk, with security code, record-update time, listing date, security subcategory, price-limit type, upper/lower prices and product-status flags. Status flag 4 distinguishes normal/risk-warning/delisting categories. The [second-batch specification](https://www.sse.com.cn/services/tradingtech/data/c/10821672/files/b0c52e43e9df447cb435b2cd6c0cbc7a.pdf) says `cpxx0202MMDD.txt` can update price-related fields after the first batch. The older [2023 file specification](https://www.sse.com.cn/services/tradingtech/historicaldata/c/10749718/files/bb052783571b4f48ba3998e00e6b50fd.pdf) documents the earlier UT/MDGW route; the current specification records that UT stopped forwarding these files in 2025. That channel change makes a single presumed retrieval route across 2024–2026 unsafe. The SSE site's “historical data” *technical-document* section is not a dated raw-file archive.

The exchange [market-data and technical-service page](https://www.sse.com.cn/transparency/services/) supplies application/contact channels. Separately, the official [SSEINFO historical-data product](https://www.sseinfo.com/services/assortment/historical/) and [product description](https://www.sseinfo.com/services/assortment/document/product/c/10010539/files/682c5b3b17d34683be0b3f810bdd6b00.pdf) describe an application-reviewed historical securities basic-information file, with fees and internal-use restrictions. They do **not** establish that this product retains original `cpxx0201/0202` batches, delivery timestamps, final pre-open corrections or the full candidate window. It is a candidate *authorized* channel, not acquired authority. No application, login or purchase was made.

### SZSE acquisition

The [SZSE official file-exchange specification](https://docs.static.szse.cn/www/marketServices/technicalservice/notice/W020180523596999490643.pdf) identifies `cashauctionparams` as per-security XML published before market open, with `PriceLimitSetting`, `HasPriceLimit`, `ReferPriceType`, `LimitType`, rate and absolute fields. The [SZSE FAQ](https://www.szse.cn/www/marketServices/technicalservice/introduce/P020180328467244590967.pdf) warns that `LimitUpAbsolute` and `LimitDownAbsolute` have no meaning when `LimitType=1` (rate); no parser may treat both as authoritative prices. The [2025 technical notice](https://www.szse.cn/marketServices/technicalservice/notice/t20250627_614645.html) explicitly pairs `cashauctionparams` limit rates with `securities` `SecurityType` and `SecurityStatus/Status` codes 4 (ST) and 5 (*ST) for main-board risk warnings. That notice discussed a **proposed** technical change; it is not proof that any 2026-07-03/07-06 production row had a given value. The [2025 file specification](https://www.szse.cn/www/marketServices/technicalservice/interface/P020250905554214018315.pdf) describes FTS distribution and distinguishes preliminary `pre` files from the later unprefixed pass, which participants should treat as controlling. Request both passes and all corrections, not a stripped result CSV.

The [daily securities-file notice](https://www.szse.cn/marketServices/technicalservice/notice/t20170803_521026.html) establishes pre-open `securities_YYYYMMDD.xml` distribution to market participants. The [FAQ](https://www.szse.cn/www/marketServices/technicalservice/introduce/P020180328467244590967.pdf) maps ST/*ST and delisting-consolidation status to this file, but also says remaining delisting-consolidation days are **not** in the static file and require the delisting notice. The official [SZSE market-data authorization contact](https://www.szse.cn/English/about/contactus/index.html) is a request route, not a guarantee of historical FTS-file retention. No four-day raw `cashauctionparams` or `securities` file was identified in the workspace or official public material reviewed.
